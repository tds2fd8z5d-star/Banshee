# Бот записи к мастеру (маникюр · брови · ресницы)

Telegram-бот для частного мастера: клиенты сами записываются на свободное время,
получают напоминания, а мастер управляет расписанием, услугами и записями прямо в Telegram.

**Стек:** Python 3.11 · aiogram 3 · SQLite (aiosqlite) · APScheduler

## Возможности

**Клиент**
- `/start` — приветствие и меню: «Записаться», «Мои записи», «Цены», «Контакты».
- Запись: услуга → дата (ближайшие 14 дней, только дни со свободными окнами) →
  время (с учётом длительности услуги, перерывов и занятых слотов) → имя и телефон
  (кнопка «Поделиться контактом» или ввод вручную) → подтверждение.
  Постоянному клиенту контакты повторно не нужны.
- «Мои записи» — будущие записи с кнопками «Перенести» и «Отменить».
- Напоминания за 24 часа и за 2 часа с кнопками «Подтверждаю» / «Отменить».

**Мастер** (`/admin`, только для ID из `ADMIN_IDS`)
- Уведомления о каждой новой записи, отмене, переносе и подтверждении.
- Записи на сегодня / завтра / неделю (с телефонами и суммой), отмена записи с уведомлением клиента.
- Закрыть весь день или отдельные часы; список закрытого времени с кнопкой «Открыть».
- Добавить запись вручную (клиент позвонил): если у клиента есть Telegram и он уже писал боту, ему придёт уведомление.
- Услуги: изменить название, цену, длительность, скрыть/показать, добавить новую.
- Рассылка всем клиентам бота (например, «есть свободные окна на пятницу»).
- Утренняя сводка записей на день (время настраивается).

**Надёжность**
- Нельзя записаться на прошедшее время, ближе чем за `min_lead_minutes`, на занятое, закрытое
  или пересекающееся время. Перед сохранением время проверяется повторно под блокировкой,
  а в БД стоит уникальный индекс — двойная запись невозможна даже при одновременных нажатиях.
- Повторное нажатие «Подтвердить» не создаёт вторую запись.
- Неверный ввод (буквы вместо телефона, стикер вместо имени и т.п.) — вежливая подсказка.
  Все ошибки перехватывает глобальный обработчик: бот пишет в лог и продолжает работать.
- Напоминания хранятся флагами в БД и проверяются каждую минуту, поэтому
  переживают перезапуск бота, а при переносе записи заводятся заново.

## Структура

```
beauty_bot/
├── bot/
│   ├── __main__.py      # точка входа, обработчик ошибок
│   ├── config.py        # загрузка .env и config.yaml
│   ├── db.py            # SQLite: клиенты, услуги, записи, закрытое время
│   ├── slots.py         # расчёт свободного времени (чистая логика)
│   ├── booking.py       # создание/перенос записи без двойных записей
│   ├── scheduler.py     # напоминания и утренняя сводка (APScheduler)
│   ├── keyboards.py     # инлайн-клавиатуры и callback-данные
│   ├── texts.py         # все тексты бота
│   ├── notify.py        # безопасная отправка сообщений
│   ├── states.py        # состояния FSM
│   └── handlers/
│       ├── commands.py  # /start, /admin, /cancel
│       ├── booking.py   # сценарий записи (клиент, перенос, ручная запись)
│       ├── client.py    # меню, мои записи, отмена, подтверждение
│       ├── admin.py     # панель мастера
│       └── fallback.py  # ответ на всё непонятное
├── tests/               # pytest: слоты, двойные записи, сквозной сценарий
├── config.yaml          # НАСТРОЙКИ МАСТЕРА
├── .env.example
├── requirements.txt
├── Dockerfile, docker-compose.yml
└── deploy/beauty-bot.service   # unit для systemd
```

## Настройка под мастера

1. **Создайте бота** у [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.
2. **Узнайте Telegram ID мастера** — например, у [@userinfobot](https://t.me/userinfobot).
3. Создайте `.env` из примера:
   ```bash
   cp .env.example .env
   ```
   ```ini
   BOT_TOKEN=1234567890:AA...
   ADMIN_IDS=123456789          # несколько — через запятую
   ```
4. Отредактируйте **`config.yaml`**:
   - `master` — имя, специализация, адрес, телефон, ссылка на портфолио;
   - `schedule` — рабочие дни (`mon`…`sun`), часы и перерывы; `null` = выходной;
   - `services` — название, цена, длительность в минутах;
   - `booking` — горизонт записи (14 дней), шаг сетки, минимальное время до записи,
     за сколько часов клиент ещё может сам отменить/перенести запись;
   - `reminders` — за сколько часов напоминать, время утренней сводки мастеру.

> Услуги из `config.yaml` загружаются в базу **только при первом запуске**. Дальше
> мастер меняет их в боте (`/admin` → «Услуги и цены»). Чтобы заново загрузить список
> из файла, удалите базу `data/bot.sqlite3` (при этом удалятся и записи).

> Мастеру нужно один раз написать боту `/start` — иначе Telegram не даст боту прислать
> ему уведомление первым.

## Локальный запуск

```bash
cd beauty_bot
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # и заполните
python -m bot
```

База создаётся автоматически в `data/bot.sqlite3`.

Тесты:

```bash
pip install -r requirements-dev.txt
pytest
```

## Деплой

### Вариант 1. Docker (рекомендуется)

На сервере с установленными Docker и Docker Compose:

```bash
git clone <ваш-репозиторий> && cd <репозиторий>/beauty_bot
cp .env.example .env && nano .env      # токен и ID мастера
nano config.yaml                       # данные мастера
docker compose up -d --build
docker compose logs -f                 # логи
```

- База хранится в `./data` на хосте и не пропадает при пересборке.
- `config.yaml` подключён томом: после правки достаточно `docker compose restart`.
- Обновление кода: `git pull && docker compose up -d --build`.

### Вариант 2. systemd

```bash
sudo useradd --system --create-home --home-dir /opt/beauty-bot beautybot
sudo cp -r beauty_bot/. /opt/beauty-bot/
cd /opt/beauty-bot
sudo python3.11 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env && sudo nano .env && sudo nano config.yaml
sudo chown -R beautybot:beautybot /opt/beauty-bot
sudo chmod 600 /opt/beauty-bot/.env

sudo cp deploy/beauty-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now beauty-bot
journalctl -u beauty-bot -f            # логи
```

После правки `config.yaml`: `sudo systemctl restart beauty-bot`.

### Резервная копия

Вся информация — в одном файле `data/bot.sqlite3`. Простой ежедневный бэкап (cron):

```bash
0 4 * * * sqlite3 /opt/beauty-bot/data/bot.sqlite3 ".backup '/opt/beauty-bot/backup-$(date +\%F).sqlite3'"
```

## Как перенастроить под нового мастера

1. Новый бот у @BotFather → новый `BOT_TOKEN`.
2. Новый `ADMIN_IDS` в `.env`.
3. Правка `config.yaml` (контакты, график, услуги).
4. Чистая база: удалите/не копируйте `data/`.
5. Запуск — тексты, кнопки и логика менять не нужно. Все фразы собраны в `bot/texts.py`.

## Примечания

- Часовой пояс задаётся в `config.yaml` (`Europe/Moscow`); всё время в боте и в базе — в нём,
  независимо от часового пояса сервера.
- Все кнопки бота — инлайн. Единственное исключение — «Поделиться контактом»: Telegram
  разрешает запрос номера только через обычную клавиатуру; она скрывается сразу после ввода.
- Состояния диалога хранятся в памяти: если бот перезапустить посреди записи, клиент
  увидит «шаг устарел» и начнёт заново. Сами записи хранятся в БД и не теряются.
- Если запись пересекается с часами, которые мастер закрыл позже, она не отменяется
  автоматически — бот предупредит мастера и покажет такие записи.
